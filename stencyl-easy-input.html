Easy Input System

The bittyBIG Easy Input System gives Stencyl one unified input layer for keyboard, mouse, gamepads, touch, mobile gestures, device motion, and virtual controls. Build named Actions once, assign Input Sources to them, then choose an Action Map per Input Slot.

Quick StartCore ConceptsDropdown ReferenceBlock Glossary

Project Setup in Stencyl

1. Install and enable the extension

  1. Open Settings → Extensions.
  2. Install bittyBIG Easy Input System.
  3. Enable it for the project.

2. Use the Easy Input palette

The extension initializes its input backends automatically. You do not need to create a separate manager Actor just to begin using the public blocks.

Create an Action Map, make it active while defining Actions, then assign the map to one or more Input Slots.

Recommended workflow: define gameplay in Actions first. Use raw input reporters/events only when you genuinely need the underlying device data.

Quick Start Guide

Create a map, assign one or more Input Sources to named Actions, give the map to an Input Slot, then read the Action instead of checking each physical input separately.

Create Action Map Basic
Set Action Move to Keyboard Common / Symbol WASD
Set Action Jump to Keyboard Space
Set Action Jump to Controller Button South
Set Input Slot 0 Action Map to Basic
Action Jump is Pressed for Input Slot 0

Multiple inputs can share one Action

Calling Set Action again with the same Action name adds another binding of the same kind. For example, Space and Button South can both trigger Jump.

Input Slots choose maps

Action Maps are definitions. Input Slots select which map they use. This lets different players or modes use different mappings without redefining the physical input system.

Core Concepts

Input Source — A typed description of an input that can be assigned to an Action. Sources can be digital/button, analog/scalar, or vector.

Action — A gameplay-facing name such as Jump, Shoot, Move, Aim, or Pause. Game logic should usually read Actions instead of physical devices.

Action Map — A named collection of Action definitions and their bindings.

Active Action Map — The map currently being edited by Set Action and Digital Vector setup blocks. This is separate from the map an Input Slot is using.

Input Slot — A player/input routing slot. Controller ports map naturally to slots, while keyboard, mouse, touch, gestures, and virtual controls can route through the maps that use them.

Digital Input — On/off input with Down, Pressed, and Released state.

Analog Input — One numeric value, such as a trigger, stick axis, mouse delta, or Motion axis.

Vector Input — Two numeric components, X and Y, such as a stick, mouse movement, Motion pair, or Digital Vector.

Digital Vector — Four digital directions combined into a Vector Action. Each direction can contain more than one digital input.

Combination Inputs — Multiple digital Input Sources that must all be held together for the Action to be Down.

Raw Input — Physical/device-level values and lifecycle events. Useful for drawing, custom touch logic, diagnostics, or behavior that the Action layer does not model.

Gesture Input — Higher-level interpretation of touch or device movement. One-shot gestures pulse Pressed/Released; Hold and Drag remain Down until they end.

Physical / Virtual Input → Input Source → Action Map → Input Slot → Action → Gameplay
Action kind is stable. Once an Action exists as digital, analog, or vector inside a map, the system will not silently change it to another kind.

Platform Notes

AreaCurrent behavior
Keyboard / MouseOpenFL/Stencyl keyboard and mouse input. Mouse position is reported in stage coordinates; movement/wheel values are accumulated per frame.
GamepadsNormalized digital buttons, analog sticks/triggers, vectors, connection events, controller Name/ID, and up to the system’s configured Input Slots. Deadzones are currently global rather than per Input Slot.
TouchUses OpenFL multi-touch IDs and stage coordinates. Virtual controls consume their owned touches before raw Touch events and gesture recognition, preventing duplicate input.
Android MotionAcceleration uses the raw accelerometer stream. Motion uses Android linear acceleration with gravity removed and normalized to g. Orientation uses TYPE_ROTATION_VECTOR. Gyro uses raw TYPE_GYROSCOPE radians/second.
Other Motion targetsThe OpenFL accelerometer path remains available where supported. The native iOS Core Motion Gyro/Orientation bridge is intentionally not implemented in this version; hooks/comments are retained for later work.

Slide RightOne-shot during the touch after the minimum duration and distance are reached moving right.

Pinch OutTwo-finger one-shot pulse whenever finger distance increases by the configured minimum. Re-baselines after each pulse so it can repeat without lifting.

Rotate RightTwo-finger clockwise rotation pulse after Rotate Minimum Degrees. Re-baselines after each pulse.

FAQs

Should I read physical inputs directly or use Actions?

Use Actions for normal gameplay. Physical Input Sources should generally be assigned to Actions, so keyboard, controllers, touch gestures, and virtual controls can share the same gameplay logic. Use raw reporters/events when the raw lifecycle or sensor value is itself important.

What is the difference between Pressed, Down, and Released?

Pressed is the frame an input begins. Down stays true while it is held. Released is the frame it ends.

What is the difference between Tap, Long Press, Hold, Drag, Slide, and Swipe?

Tap is a quick mostly stationary release. Long Press is a one-shot event after holding mostly still. Hold is the sustained state that begins at that same long-press point. Drag is sustained movement after crossing Drag Minimum Distance. Slide is a directional one-shot recognized while the finger is still down. Swipe is a fast directional one-shot classified on release. Drag can therefore begin before Slide or Swipe.

Why can Tap fire before Double Tap or Triple Tap?

Tap is intentionally immediate. The first qualifying release emits Tap immediately; later qualifying taps can then emit Double Tap and Triple Tap. This avoids delaying ordinary taps while waiting to see whether another tap arrives.

Can Hold and Drag both be Down at once?

Not for the same touch. If a held touch moves far enough to become a Drag, Hold releases first and Drag becomes Down.

Why does Drag often print before Slide or Swipe?

Drag is a sustained state and can begin as soon as its movement threshold is crossed. Slide needs its own distance plus minimum duration, while Swipe is classified at release. The order is intentional.

Do virtual controls also trigger raw Touch and touch gestures?

No. A virtual control consumes the touch it owns before raw Touch/gesture processing, preventing one finger press from becoming both a virtual-control input and a second gesture/raw input.

What is the difference between Acceleration, Motion, Rotation, Orientation, and Gyro?

Acceleration is the raw accelerometer and includes gravity. Motion is movement acceleration; on Android it uses gravity-free linear acceleration. Orientation is the device’s current Pitch/Roll/Yaw. Rotation is the change in orientation between updates. Gyro is raw angular velocity; on Android it is radians per second.

Does Shake use the Gyro?

No. Shake uses strong alternating linear-Motion reversals. Gyro remains a raw angular-velocity reporter.

Are controller deadzones per controller?

Not yet. Stick and Trigger deadzones are global in this version. The controller-port field is ignored when the selected reporter is Stick Deadzone or Trigger Deadzone.
